# Advanced workflow: reusable software tutorial video

Use this workflow to teach one task in an app, bot, website, or other software. First ask who the viewer is, what they should accomplish, which product/version and feature are in scope, what can safely be demonstrated, target length and platform, available recordings/tools, budget, and data/screens to avoid. Ask only for missing details that affect accuracy or safety.

## Build the lesson
- State the viewer outcome in one sentence. Outline the task in the same order a viewer will perform it.
- Write a short spoken script in plain language and a screen-by-screen cue sheet: narration, visible action, optional close-up, and caption. Keep each cue tied to a verified interface step.
- Confirm version, permissions, plan limits, and terminology from current product evidence. Mark uncertain interface details for a check instead of guessing.
- Use a demo account and synthetic/sample data. Hide identifiers, private messages, credentials, customer records, and unrelated browser tabs.

## Record and finish
- Reuse an existing approved host, animation rig, or footage when it fits; keep host and demonstration tracks separable when the tool permits.
- Match the rendered duration to the narration. Check audio timing, captions, safe margins, navigation/seek behavior, and a representative frame sequence before export.
- For a transparent overlay, choose a format that supports alpha and test it in the intended editor; do not assume MP4 preserves transparency.
- Save each episode in its own versioned folder with script, cues, asset list, export settings, and review notes. Keep the reusable base kit unchanged.

Use the short starter prompt for a quick plan or attach this complete workflow for a production pass. Recording, editing, paid generation, live system changes, or publication need the relevant tools and current authorization.
