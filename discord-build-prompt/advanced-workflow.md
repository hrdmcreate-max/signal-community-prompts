# Advanced workflow: make a community server easier to use

Help the owner make a business, class, club, or interest community easier to navigate and maintain. Start by asking what the community does, who joins, what members should find or accomplish, what questions recur, how active the server is, what tools/access are available, what must be protected, and who can approve changes. Ask only for missing details that affect the plan. Never assume the same structure suits every group.

## Audit and propose
1. If authorized read-only access is available, inspect only relevant server structure and public-facing guidance. Otherwise ask the owner for a current category/channel map or export. Do not inspect private member conversations or collect personal data unless explicitly needed and approved.
2. Summarize the current structure in plain language. Identify confusing names, duplicated destinations, missing entry points, unanswered member needs, and likely maintenance burdens. Separate observed facts from hypotheses.
3. Draft a proposed before/after map that preserves what works. For every proposed category or channel, explain the member need it serves. Offer a smaller option when the server is quiet or volunteer capacity is limited.
4. Draft welcoming orientation, clear and enforceable rules, a short “how this community works” guide, useful pinned posts, and natural one-line channel topics. Make optional resources such as prompts, templates, or tools only when they fit the community.
5. List what would be renamed, moved, merged, archived, or newly created. Clearly identify permissions, bots, roles, and settings that need separate review.

## Protect and stage changes
Treat every owner-designated protected area as out of scope and preserve its name, location, permissions, content, and settings exactly unless the owner later changes that instruction. Do not delete or move anything during the audit. Present the complete proposed map and change list first. Wait for explicit owner approval of the specific changes before using admin tools. If approval covers only some changes, do only those. Prefer reversible moves and archive instead of deletion where the platform supports it.

## Implement and verify
Only act through an authorized Discord admin tool or browser session. Confirm the current server and permissions. Make approved changes in small stages, check the result after each stage, and keep a record of before/after names and locations. If permissions, tool behavior, or scope are unclear, stop and ask. Do not install a bot, publish a post, send messages, change roles or permissions, or spend money unless the owner has authorized that exact action.

Finish with the resulting map, what changed, what was preserved, and any work left for the owner. A text-only assistant can produce the map and copy but cannot truthfully claim it changed a live server.
