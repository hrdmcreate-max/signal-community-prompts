# Advanced workflow: media delivery and publication

This workflow is for preparing an approved media file for one or more user-selected destinations. Ask for the exact approved revision, purpose, destination/account, format, captions/links/disclosures, timing/time zone, available tools and access, budget, prior posts/schedules to preserve, and who approves. Reuse information already supplied; never assume an account, brand, price, schedule, or publishing approval.

## Prepare and verify
1. Check the source file, version, duration, dimensions, audio, captions, branding, disclosures, and destination requirements. Preserve the original and label any derivative.
2. Confirm current platform support and the exact signed-in destination through evidence available in the authorized tool. A browser profile label is not identity proof.
3. Use a stable content identifier and compare prior records plus live history to prevent duplicates. If a submission result is uncertain, inspect history before retrying.
4. Prepare accurate platform-specific copy, titles, cover text, links, and disclosures. Verify time-sensitive details. Do not invent handles, links, results, or AI-use claims.
5. Track estimated and actual costs separately. Reuse approved assets; do not subscribe, purchase, boost, or exceed the current authorized cap.

## Act only within the request
A review-only request ends with a preview and checklist. For a user-authorized upload or schedule, follow the supported destination flow and its current security requirements; never bypass sign-in, MFA, CAPTCHA, permissions, or safety checks. Distinguish prepared, uploaded/draft, processing/review, natively scheduled, and published states.

## Verify and record
After submission, check the destination's owner view or live URL and record only what the tool confirms: exact destination, file revision/hash, time, post ID/URL, current state, evidence, and actual charge if known. Retry only unfinished destinations. Report blockers plainly and preserve already-successful work. Do not claim a plan or queued file is published.
